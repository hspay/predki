# Predki

**Путешествие, которое вы уже совершили.** Predki помогает вместе с родными восстановить путь своей семьи: кто были ваши предки, где они жили и куда переезжали. Из этого складываются древо, карта переездов за сто лет и в итоге книга о семье.

Сайт: [predki.me](https://predki.me) · интерфейс на русском и английском.

## Что умеет

- **Древо** — интерактивное, с портретами, линиями отца и матери, браками, партнёрами, бывшими и приёмными детьми. Родство подписывается само: «двоюродная бабушка», «сват», «предок в 9-м колене».
- **Карточка человека** — даты, места, история, события и переезды, фото и документы (просмотр и скачивание), питомцы.
- **Карта жизни семьи** — переезды всех родственников на одной карте.
- **Заполнить пробелы** — что ещё неизвестно о семье, и ссылка для родственника: он отвечает без регистрации, вы принимаете или отклоняете ответы.
- **Главы** — путь из коротких заданий; каждая глава открывает следующий раздел.
- **Альбом** — наклейки за достижения, Хранитель — личная страница с прогрессом, Паспорт семьи — карточка для соцсетей.
- **Календарь** памятных дат и **Книга семьи** (в работе).
- **Демо-древа** для знакомства без своих данных.
- Аккаунт через Google или почту; без аккаунта древо хранится в браузере. Экспорт и импорт в JSON.

## Стек

React 18 + TypeScript + Vite · Supabase (вход, база, хранилище файлов) · GSAP для анимаций · хостинг на GitHub Pages.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # проверка типов и сборка в dist/
```

Нужен Node.js 18+. `VITE_PREVIEW=1 npm run dev` запускает тестовую сборку без аккаунта и лендинга, с панелью «Превью» для быстрого прохождения глав. В рабочий сайт эта панель не попадает.

## Публикация

Каждый push в `main` собирает приложение и выкладывает его на GitHub Pages (`.github/workflows/deploy.yml`). Пути в сборке относительные, поэтому сайт работает и на своём домене, и по адресу GitHub.

## Сервер: Supabase

- **Вход** — Google и почта с паролем.
- **Таблица `trees`** — одно древо на аккаунт. Правила доступа (RLS): каждый видит и меняет только своё.
- **Хранилище `media`** — закрытое; фото и документы лежат в папке пользователя, в древе хранится только ссылка на файл.
- **Ссылки для родных** — `supabase/share-links.sql`: таблицы `share_links` и `suggestions`, гость работает только через функции `shared_tree` и `submit_suggestion`.

Ключ в коде — публичный ключ Supabase для браузера; данные защищают правила доступа на сервере, а не секретность ключа.

## Что где лежит

```
src/
  App.tsx, main.tsx       каркас приложения; ссылка ?s=… открывает страницу родственника
  pages/                  Древо, Альбом, Карта, Пробелы, Хранитель, Книга семьи, Настройки
  components/             карточка человека, просмотр файлов, меню, главы, лендинг, вход, паспорт, календарь
  lib/core.ts             данные семьи (S), сохранение, синхронизация, навигация, даты
  lib/cloud.ts            Supabase: вход, загрузка и сохранение древа
  lib/media.ts            фото и документы в хранилище
  lib/invites.ts          ссылки «Попросить заполнить» и ответы родных
  lib/progress.ts         достижения и наклейки
  lib/chapters.ts         главы и «Следующая остановка»
  lib/treeLayout.ts       раскладка древа
  lib/kinship.ts          названия родства
  lib/mapview.js          карта
  lib/i18n.ts             тексты RU + EN
  lib/demoFamilies.ts     демо-древа
  design.css, chapters.css  оформление (поверх styles.css)
public/privacy.html       политика конфиденциальности
supabase/                 SQL для сервера
```

Как устроены данные: семья лежит в `S`, любое изменение идёт через `commit()` — он сохраняет данные, пересчитывает достижения и главы и перерисовывает интерфейс.
